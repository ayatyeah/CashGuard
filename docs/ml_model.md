# ML-часть: как устроена и как обучена модель

## Пайплайн (`app/analyzers/ml.py` → `MLAnalyzer`, интерфейс STACK.md §4)

```
видео ─► кадры 2 fps ─► восприятие (готовые веса, ONNX/torch CPU)
                         ├─ YOLOX-M (COCO) — люди и предметы на полном кадре
                         ├─ YOLOX-S (COCO) — мелкие предметы на увеличенном кропе рабочей зоны
                         ├─ RTMPose-m — 17 точек позы на каждого человека
                         └─ CLIP ViT-B/32 — эмбеддинг кропа рабочей зоны (zero-shot пробы «пьёт», «телефон»)
      ─► сцена (app/ml/events.py)
           ├─ трекинг людей (IoU + венгерский алгоритм)
           ├─ кассир = присутствует дольше всех, неподвижен, крупный; место = её сидячий эпизод
           └─ посетитель в комнате vs прохожий за стеклом — ОБУЧЕННАЯ логистическая регрессия по треку
      ─► кандидаты событий (app/ml/candidates.py), всё в долях роста кассира — не зависит от ракурса
           ├─ leave        кассир ушла с места и не вернулась: экран ноутбука, предметы на столе, время у сейфа
           ├─ entry        человек вошёл: вернулась ли область двери к исходному виду через 4–12 с
           ├─ crowd        посетитель не садится (стоит у стола) / 3+ человек в комнате
           ├─ short_visit  посетитель уходит < 20 с после подхода к столу
           ├─ drink        CLIP «пьёт кофе» на кропе кассира / стакан у кисти
           └─ phone        телефон у кисти кассира (строгое правило)
      ─► скорер (app/ml/scorer.py + models/scorer.json) — ОБУЧЕННЫЕ пороги ─► события
      ─► описание + норматив из app/rules/norms.yaml (app/ml/pipeline.py)
```

## Модели и лицензии (все допускают коммерческое использование)

| Модель | Назначение | Лицензия | Источник |
|---|---|---|---|
| YOLOX-M, YOLOX-S (COCO) | детекция людей/предметов | Apache-2.0 | Megvii, GitHub releases |
| RTMPose-m body7 | поза (17 точек) | Apache-2.0 | OpenMMLab (через rtmlib, Apache-2.0) |
| CLIP ViT-B/32 | семантика кропа | MIT | openai/clip-vit-base-patch32 |
| track_model.json | посетитель vs прохожий | наша (обучена на train) | `scripts/train_tracks.py` |
| scorer.json | пороги по типам нарушений | наша (обучена на train) | `scripts/train_scorer.py` |

Всё работает локально на CPU (onnxruntime + torch CPU): Linux и macOS arm64. Интернет нужен только один раз для
`scripts/download_models.sh`. Облачных AI-сервисов нет. Распознавания лиц нет: люди различаются только по положению/размеру трека.

## Что обучено и на чём

Данные: 30 train-видео (`configs/split.json`); 10 test-видео отложены и не использовались ни для обучения, ни для подбора
порогов. Типы нарушений в разметке организаторов не указаны — мы разметили их сами (`configs/train_annotations.json`).

1. **Классификатор треков** (логистическая регрессия, 15 признаков трека: дистанция до места кассира, относительный рост,
   уверенность детекции и позы, неподвижность, длительность…). Метки — интервалы присутствия посетителей
   (`configs/visitors_train.json`). Leave-one-video-out: точность 0.94 (69 треков).
   Ключевой физический признак: люди за стеклом и в отражениях детектируются с меньшей уверенностью.
2. **Скорер** — по одному сильному признаку на тип нарушения с обученным порогом (max-margin decision stump):

| Тип | Признак | Порог (обучен) | Разделимость на train |
|---|---|---|---|
| workstation_unlocked | яркость экрана ноутбука / средняя яркость кадра после ухода | 1.27 | да (2 поз / 6 нег) |
| left_cash_unattended | предметы на столе / (1 + время у сейфа перед уходом / 5 с) | 0.55 | да (3 / 5) |
| door_left_open | доля изменившихся пикселей в области двери через 4–12 с после входа | 0.134 | да (3 / 7) |
| unauthorized_person | доля времени, которую посетитель стоит у стола | 0.66 | да (4 / 6) |
| food_drink | CLIP «пьёт кофе» на кропе кассира | 0.57 | да (2 / 10) |
| count_not_in_client_presence | посетитель ушёл < 20 с после подхода (правило) | — | позитивы только |
| phone_use | телефон у кисти ≥ 4 с + CLIP (правило, в train позитивов нет) | — | — |

   Почему пни, а не бустинг/нейросеть: на 1–5 примеров на тип любая многомерная модель переобучается
   (проверено: логрегрессия по 6 признакам дала LOVO-точность 0.60 против 0.77 у пней).

## Метрики

**Train, leave-one-video-out** (каждое видео оценено моделью, обученной без него), 30 видео:
точность вердикта **0.77**, precision 0.91, recall 0.62; ошибка таймкода — медиана 2.2 с, все найденные ≤ 5 с;
тип угадан в 90% найденных нарушений.

**Test (10 отложенных видео, полный прогон анализатора с нуля, модель заморожена в коммите 845a536 до оценки):**

| Видео | Разметка | Модель | Итог |
|---|---|---|---|
| X-1, Х-20, Х-22, Х-38 | нарушение | — | пропуск |
| Х-13 | нарушение (47 с) | unauthorized_person @ 0.0 с | вердикт совпал, но событие не то (таймкод неверный) |
| Х-16 | норма | door_left_open + unauthorized_person | ложное срабатывание |
| Х-14, Х-19, Х-23, Х-29 | норма | — | верно |

Точность вердикта **0.50**, recall 0.20, precision 0.50; правильно локализованных нарушений — 0 из 5.
Вывод: детекторы покрывают типы, встреченные в train (уход с места, дверь, посторонний, напитки), а нарушения
в test, по-видимому, другие (работа с деньгами/документами), которые CV-признаками без VLM не видны; выборка мала
(5 позитивов). Ошибки на test не разбирались по кадрам, чтобы test остался чистой отложенной выборкой.
Время: 0.95–1.1× длительности видео на Ryzen 7 5800H (видео 143 с → 140 с).

## Ограничения и известные ошибки
- Не распознаются (нет надёжного визуального признака на CPU-моделях): приём денег без документа клиента (X-2),
  смешение денег разных клиентов (X-4), личные вещи на столе (X-40 — детектор путает сумку со счётной машинкой),
  вложение отбракованных купюр в пачку (X-44). Это задачи для VLM-проверки кандидатов (план в STACK.md §8).
- Стеклянная стена: за прозрачным стеклом человек выглядит почти как в комнате; момент выхода определяется неточно,
  поэтому «уход» = кассир покинула место и не вернулась, а вывод делается по состоянию стола/экрана.
- Признак двери откалиброван на 3 позитивах; на ракурсах, где дверь не видна, событие не формируется (пропуск, не ложное срабатывание).
- Таймкод «ухода» ставится на начало прохода к двери; организаторы иногда отмечают момент у двери (ошибка до ~3 с).
- Скорость на Ryzen 7 5800H: ≈1× реального времени (+8 с на загрузку моделей); на Apple M3 быстрее.
  При нехватке бюджета анализатор снижает частоту кадров (режим `cheap`).

## Воспроизведение
```bash
uv venv --python 3.11 .venv && uv pip install -r requirements-ml.txt   # (+ torch CPU)
bash scripts/download_models.sh
python scripts/extract_features.py data/train/videos data/test/videos --out data/cache --fps 2
python scripts/extract_clip.py --cache data/cache
python scripts/train_tracks.py      # → models/track_model.json (+ LOVO)
python scripts/train_scorer.py      # → models/scorer.json (+ LOVO)
python scripts/evaluate.py --split test
python scripts/analyze_video.py path/to/video.mov   # JSON в формате API жюри
```
