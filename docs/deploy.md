# Запуск общего сервера CashGuard

Как поднять на своём ноутбуке сервис с локальной моделью, чтобы вся команда (и жюри) пользовалась им через сайт.
Всё работает в Docker: Postgres, Go-бэкенд с ML-моделью, сайт и публичный туннель Cloudflare.
Видео и кадры никуда не уходят — облачных AI нет, туннель только пробрасывает сайт наружу.

## Что нужно

- Ноутбук, который будет **постоянно включён**: 8 ГБ RAM или больше, ~15 ГБ свободного места.
- **Docker Desktop**: <https://www.docker.com/products/docker-desktop/>.
  - Settings → Resources → Memory: **не меньше 4 ГБ**.
  - Settings → General → включить **Start Docker Desktop when you sign in**.
  - Windows: Docker Desktop с WSL 2 (предлагается при установке).
- **Git**.
- Файл **`.env`** — получить у Алдияра лично (не через общий чат). В нём пароль базы и API-ключ;
  ключ общий для всей команды и жюри, поэтому свой не придумывать.

## Запуск

```bash
git clone https://github.com/ayatyeah/ForteWin.git
cd ForteWin
# положить полученный .env в корень ForteWin (рядом с compose.yaml)
```

macOS / Linux:

```bash
scripts/deploy.sh
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1
```

Первый запуск — **10–15 минут**: скачиваются torch и веса моделей (YOLOX, RTMPose, CLIP) в образ.
В конце скрипт печатает строку `Публичный адрес: https://….trycloudflare.com` — этот адрес отправить в чат команды.

Проверка:

```bash
curl https://<адрес>/api/health        # {"demo":false,"status":"ok"}
```

`"demo":false` значит, что видео анализирует настоящая модель.

## Скорость

Модель работает **на процессоре** (видеокарта не нужна и сейчас не используется). Чтобы уложиться в 5 минут на видео,
анализатор сам снижает частоту кадров, исходя из `FORTE_COST_PER_FRAME` — сколько секунд уходит на один кадр
(по умолчанию 1.2, замер на Apple M3 8 ГБ). Свой замер виден в логах: `docker compose logs backend | grep timings` →
`perception / frames`. Если на этом ноутбуке выходит меньше, добавить в `.env`, например, `FORTE_COST_PER_FRAME=0.6`
и снова запустить скрипт — длинные видео будут анализироваться с полной частотой кадров.

## Чтобы сервер не отключался

Адрес туннеля **меняется при перезагрузке** ноутбука или Docker — после неё запустить скрипт ещё раз и разослать новый адрес.
Контейнеры сами поднимаются после перезапуска Docker.

macOS:

```bash
sudo pmset -a sleep 0 disksleep 0     # не засыпать
sudo pmset -a autorestart 1           # включаться после отключения питания
caffeinate -dims                      # держать открытым в отдельном терминале
```

Windows: Параметры → Система → Питание → «Переводить в спящий режим» — **Никогда** (от сети);
действие при закрытии крышки — «Ничего не делать».

Ноутбук держать **на зарядке**.

## Обновление после изменений в репозитории

```bash
git pull
scripts/deploy.sh                    # Windows: scripts\deploy.ps1
```

Пересоберутся только изменённые части; туннель и адрес не меняются, если не перезапускать Docker.

## Полезные команды

```bash
docker compose ps                                  # состояние сервисов
docker compose logs -f backend                     # логи анализа (строка timings=… на каждое видео)
docker compose logs tunnel | grep trycloudflare    # текущий публичный адрес
docker compose --profile public down               # остановить (данные сохраняются; не добавлять -v)
```

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `Docker не запущен` | открыть Docker Desktop, дождаться «Engine running» |
| сборка падает на `download_models.sh` | нет интернета или GitHub недоступен — повторить скрипт |
| все задания `failed`, в логах `$'\r': command not found` | репозиторий склонирован с CRLF до появления `.gitattributes`: `git rm --cached -r . && git reset --hard` |
| адрес не открывается | ноутбук уснул или Docker перезапускался — `scripts/deploy.sh`, разослать новый адрес |
| `"demo":true` | в `.env` должно быть `DEMO_MODE=false`, затем снова запустить скрипт |

Одновременно должен работать **один** общий сервер: когда этот поднят, на других ноутбуках сервис остановить,
чтобы у команды и жюри был один адрес.
