# K1. Recall без новых данных: что реально даёт test-time политика (и что нет)

Агент K1 из 10. Все числа ниже посчитаны из `data/train_rows.json` (215 кандидатов, 40 видео) той же процедурой
leave-one-cabinet-out (LOCO), что в `scripts/train_scorer.py`; воспроизводится базовая точка **TP=12 / FP=0 / FN=9,
acc 0.775, recall 0.57, loss(2·FN+FP)=18**. Скрипты: `/tmp/claude-1000/-home-yeahayat-ForteWin/0592e13b-8dd5-4d51-b32b-c9dfe0c0ef77/scratchpad/{nearmiss,sweep2,zero_pos,final_variant}.py`
(тяжёлые модели не запускались, `.mov` не открывались).

## TL;DR

1. **Гипотеза «пропуски — это кандидаты чуть ниже порога» не подтверждается.** Из 9 LOCO-пропусков ни у одного нет
   кандидата *правильного* типа с p ∈ [0.2, 0.5). У 6 из 9 (X-1, X-2, Х-13, Х-44, Х-40, Х-32) нет кандидата нужного
   вида вообще или нет референса для его порога. Понижение порога, TTA, 4 fps, гистерезис — всё это настраивает
   скорер, а узкое место — **генерация кандидатов**. Потолок любой test-time политики при 0 FP: 14/21 (recall 0.67).
2. **Единственная test-time тактика с измеримым выигрышем — порог «из нормы» (one-class) для стампов без
   позитивов в обучающей выборке**: `thr = (1+k)·max(признак на видео без этого нарушения)`, k ∈ [0.25, 1.0] — плато.
   LOCO: **TP 12→14, FP 0→0, acc 0.775→0.825, loss 18→14**, медиана таймкода 1.5→1.0 с (Х-20 сейф 5.5 с vs 5 с,
   Х-46 напиток 10–12 с vs 11 с). Это ровно сценарий жюри «тип, которого не было в обучении, но признак есть».
   Цена: 0 с инференса, ~40 строк кода.
3. «Второй шанс» (понизить порог, если событий 0): при τ₂=0.35 LOCO +1 TP (Х-32, но **тип неверный**: `safe_key`
   вместо `door`), запас до ближайшего нормального (Х-31, p=0.34) — 0.06. P(нарушение | max p ∈ [0.2, 0.5)) = 2/4 —
   монетка. **Вердикт не переключать**; отдавать как `low_confidence_observations` (продукт/robustness, 0 риска).
4. Априор «большинство тестовых видео — нарушения» не подтверждён данными (21/40 = 52.5 %; бывший test 5/10) и
   даёт EV ≈ +0.5 балла при огромной дисперсии и ударе по доверию на питче. Не делать.

## 2. Свипы (всё LOCO, 40 видео)

### 2.1 «Второй шанс»: если событий нет — выдать argmax-кандидат при p ≥ τ₂
| τ₂ | TP | FP | FN | loss 2FN+FP | что добавилось | что сломалось |
|---|---|---|---|---|---|---|
| 0.50 (сейчас) | 12 | 0 | 9 | 18 | — | — |
| 0.35 | 13 | 0 | 8 | 16 | Х-32 (safe_key, тип неверен) | — (Х-31 на 0.34 — запас 0.06) |
| 0.30 | 13 | 1 | 8 | 17 | | Х-31 |
| 0.25 | 14 | 2 | 7 | 16 | + Х-22 (leave_screen, тип неверен) | + Х-14 |
| 0.10 | 16 | 7 | 5 | 17 | + X-1, Х-40 (типы неверны) | 7 ложных |
| 0.00 | 21 | 19 | 0 | 19 | всё | всё |

Вывод: при цене 2:1 оптимум τ₂ = 0.35 даёт −2 loss на одном видео с неверным типом и запасом 0.06 по p (0.004 по
признаку owl_key). На жюри это ≈ +5 баллов за вердикт с вероятностью ~0.5 и −5 (+ robustness −10, если это видео
с новым ракурсом) с той же вероятностью. **EV ≈ 0, дисперсия максимальна.**

### 2.2 Глобальный порог Элкана p* = C_FP/(C_FP+C_FN) = 1/3 на всех кандидатах
τ=0.333: TP 13 / FP 1 / FN 8, loss 17 (−1). Теоретически верная рабочая точка для 2:1, но наш калиброванный p на
гранях не информативен (см. §1). Не внедрять.

### 2.3 Сдвиг порога внутри разделимого зазора (α: 0.5 = середина, меньше = ближе к негативам)
α ∈ {0.5, 0.4, 0.33}: без изменений. α=0.25: +1 FP (Х-14 safe_open). α=0.15: +1 TP (Х-22, тип неверен) / +1 FP.
Вывод: max-margin середина уже оптимальна; **«cost-sensitive сдвиг» ничего не даёт**, потому что пропуски не на грани.

### 2.4 Порог «из нормы» для стампов без позитивов (novelty fallback)
Реализация как в коде §4: референс = кандидаты этого вида на видео **без данного типа нарушения** (нормальные + другие
нарушения), минимум 3 видео, `thr = (1+k)·max(ref)`, `scale = 0.1·thr`.

| k | TP | FP | FN | acc | loss | что добавилось (t события vs разметка) |
|---|---|---|---|---|---|---|
| нет (сейчас) | 12 | 0 | 9 | 0.775 | 18 | — |
| 0.10 | 15 | 1 | 6 | 0.825 | 13 | Х-20, Х-22 (owl_key 0.0519 vs thr 0.0473), Х-46; **FP Х-43** (drink 0.17) |
| **0.25–1.0** | **14** | **0** | **7** | **0.825** | **14** | **Х-20 safe_open @5.5 (ts 5), Х-46 drink @10/12 (ts 11)** |
| 1.5 | 13 | 0 | 8 | 0.80 | 16 | только Х-46 |

Плато k ∈ [0.25, 1.0] широкое → выбор k по CV почти не переобучает; рекомендуемое **k = 0.5** (центр плато:
Х-20 p=0.98, запас Х-43 до порога drink 0.055, Х-14 safe 0.052 vs thr 0.079 — ×1.5).
Это и есть честная оценка «новый тип + новый ракурс, признак существует»: признак разработан так, что «больше = хуже»,
и одной нормы хватает для порога (так же anomalib/PatchCore ставят порог по распределению нормальных скорингов, когда
аномальной валидации нет — см. источники).

Важно про отгрузку: в финальной модели на всех 40 у каждого включённого стампа есть позитив, поэтому **пороги
`models/scorer.json` не меняются и ложных на жюри эта правка добавить не может**. Что меняется: (а) честная
LOCO-цифра для питча 0.825 / 0 FP вместо 0.775; (б) появляется путь для признаков без единого позитива
(`vlm_teller_holds_phone`: норма max=4 → thr 6 → никогда не сработает — безвредно; зонные `proto_*` — если
их значений нет в `train_rows.json`, стамп не создаётся).

## 4. Политика решения и точный код

**Политика.** (1) Событие = стамп/правило с p ≥ 0.5 (без изменений). (2) Стамп без позитивов, но с ≥ 3 референсными
видео получает one-class порог `(1+0.5)·max(ref)`; в `scorer.json` он помечен `"novelty": true` и в описании события
добавляется «порог выведен по нормальным видео». (3) Если событий нет, но есть кандидат с p ∈ [0.2, 0.5) — вердикт
`no_violation`, кандидат уходит в `low_confidence_observations` (тип, t, p, признак/порог) — для UI и питча.

### 4.1 `app/ml/scorer.py` — `fit_stump`
```python
NOVELTY_K = 0.5   # one-class threshold = (1+k)·max over reference (videos without this violation type)

def fit_stump(pos: list[float], neg: list[float], ref: list[tuple[float, str]] | None = None) -> dict | None:
    if not pos:
        # no positive example of this type: threshold from the reference distribution alone
        # (LOCO: k in [0.25, 1.0] gives TP 12→14, FP 0→0; chosen k=0.5 is the centre of the plateau)
        if not ref or len({v for _, v in ref}) < 3:
            return None
        mx = max(x for x, _ in ref)
        if mx <= 0:
            return None
        thr = float(mx * (1 + NOVELTY_K))
        return {"thr": thr, "scale": max(0.1 * thr, 1e-3), "separable": True, "novelty": True,
                "n_pos": 0, "n_neg": len(neg), "n_ref": len({v for _, v in ref}), "ref_max": float(mx)}
    pos, neg = np.array(pos, float), np.array(neg, float)
    ...  # остальное без изменений
```

### 4.2 `scripts/train_scorer.py` — `train()`: собрать `ref` и передать
```python
        pos, neg, ref = [], [], []
        for r in rows:
            if r["kind"] != kind or feat not in r["f"] or not S._gate_ok(r["f"], gates):
                continue
            if type_id in r["types"]:
                ...  # как сейчас → pos
            else:
                ref.append((r["f"][feat], r["video"]))          # any video WITHOUT this violation type
                if r["vlabel"] == 0 or kind == "safe_key" or (kind == "leave" and r["types"]):
                    neg.append(r["f"][feat])
        st = S.fit_stump(pos, neg, ref)
```
`report()` — печатать `novelty` стампы отдельной строкой («пороги из нормы: safe_open, drink_clip, …»), чтобы
протокол CV был прозрачным.

### 4.3 `app/ml/pipeline.py` (после `kept = sorted(...)[:3]`)
```python
    LOW_CONF = (0.2, 0.5)
    low = []
    if not kept:
        for c in cands:
            for type_id, p in S.score_all(c, models.scorer):      # same as score() but without the p >= 0.5 cut
                if LOW_CONF[0] <= p < LOW_CONF[1]:
                    low.append({"type_id": type_id, "t": round(c.t, 1), "p": round(p, 2), "kind": c.kind})
        low = sorted(low, key=lambda d: -d["p"])[:1]              # at most one: the single most suspicious moment
    info["low_confidence_observations"] = low
```
(`score_all` = копия `score` без `if p >= 0.5`; 6 строк.) В `app/analyzers/ml.py` пробросить `info[...]` в
`AnalysisResult` (поле `extra`/`warnings`) → API отдаёт его рядом с вердиктом; вердикт остаётся по `kept`.

## 5. План внедрения (10 строк)
1. `scorer.fit_stump(pos, neg, ref)` + `NOVELTY_K=0.5` (§4.1), `score_all` без отсечки.
2. `train_scorer.train()`: собрать `ref`, пометить `novelty` стампы; `report()` печатает их список.

   таймкод медиана 1.0 с; финальные пороги на 40 видео совпадают с текущими (diff `scorer.json` — только служебные поля).
