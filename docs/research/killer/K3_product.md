# K3. Продуктовые «killer features» для банковского жюри (≤ 8 ч, поверх React + Go + Python)

Агент K3 из 10. Дата 18.10.2026. Прочитано: `killer/CONTEXT.md`, `08_competition_tactics.md`, `SUBMISSION.md`, текст ТЗ
(`Кейс_ForteBank.docx`), `STACK.md`, `app/rules/norms.yaml`, `app/ml/pipeline.py`, `scripts/cashguard_analyzer.py`,
`src/backend/**/*.go`, `src/frontend/src/**/*.tsx`. Модели не запускались.

Критерии, на которые можно повлиять продуктом: **продукт 10** («удобство интерфейса, надёжность загрузки и обработки,
понятность результата»), **техника 10** («обоснованность архитектуры, практичность, возможность развития»), **нормативная
база 15** («точность источника и трактовки; отсутствие выдуманных ссылок и неподтверждённых юридических утверждений»).
Плюс косвенно устойчивость 10 (объяснённый пропуск лучше молчаливого) и шансы в шортлисте.

## 0. Что уже есть и чего нет (факты из кода)

Есть: загрузка одного файла drag-and-drop, история с фильтрами и 7-дневным графиком, страница проверки (вердикт-баннер,
плеер, таймлайн с маркерами событий, список событий, описание, 1–3 кадра с зумом, «Основание для проверки» =
`rule.title · rule.section` + ссылка adilet), «Скачать JSON», интерфейс RU/EN/KK (словарь `translations.ts`),
дисклеймер. Описание события уже структурное: «Наблюдается … Квалификация … Норма … Цитата «…»».

Нет (и это видно жюри):
1. **Для `no_violation` ничего, кроме пустого списка.** Ни «что проверено», ни покрытия, ни режима. Жюри не отличит
   «проверили и чисто» от «модель не нашла кассира». ТЗ FAQ-15: злоупотребление «недостаточно данных» штрафуется —
   значит, обоснованная «норма» ценится.
2. **`warnings`/`timings`/`mode` анализатора не доходят до UI**: `scripts/cashguard_analyzer.py` пишет их только в stderr,
   `domain.Job` в Go их не имеет, поэтому пункт 6 UI из `STACK.md` («предупреждения анализа, проанализировано X из Y с»)
   фактически не реализован. Признак «рабочее место кассира не найдено — вывод ненадёжен» теряется.
3. **Норма показана одной строкой** (длинное название документа · пункт). Дословная цитата, которая уже есть в
   `norms.yaml` и сверена с adilet, в UI отсутствует (обрезана до 220 символов внутри описания). Нет пометки
   «прямая норма / связанное требование» (поле `interpretive` есть в yaml, в API не передаётся). ТЗ §6 требует
   «показать связь между источником, предполагаемым нарушением и наблюдаемым фрагментом» — это именно карточка нормы.
4. **Нет «паспорта анализа»**: sha256 видео (Go его не считает), версия модели/скорера, режим `full|cheap`, кадров/с,
   время обработки. Для банка это минимальный audit trail (EU AI Act ст. 12/19: автоматическое логирование, для
   финорганизаций — в составе существующей документации, хранение ≥ 6 мес.).
5. **Нет решения контролёра** (подтвердить/отклонить с причиной) и журнала — то, что индустрия считает нормой:
   TRASSIR ActivePOS хранит флаг инцидента `new/confirmed/rejected` и эксперта, который его поставил; Veesion в FAQ
   требует «квалифицировать каждый алерт» как подозрительный/нет; Roboflow Vision Events — оценка
   correct/incorrect/inconclusive + комментарий + имя + время; Verkada — PDF-отчёт инцидента с audit log и проверкой
   целостности видео (Verkada Verify).
6. **Нет перечня типов в продукте** (ТЗ §8 п. 5 требует «перечень типов нарушений, которые распознаёт решение, с кратким
   описанием каждого») — он есть только в `docs/`. Жюри-банкиры смотрят сайт, не репозиторий.
7. Уверенность (`Event.p`) и измеренные признаки (`Event.f`) не выходят из Python; зоны (`desk_box`, `key_box`,
   `safe_zone`, трек кассира) существуют в `candidates`, но кадры отдаются «голыми».

Калибровка ожиданий: ТЗ FAQ-27 прямо говорит, что **авторизация, история, экспорт и пакетная загрузка не нужны**. Значит
баллы за них идут только через «понятность результата» и питч, а не напрямую. Поэтому экспорт/акт ниже в рейтинге по
отношению «баллы/час», но остаётся лучшим демо-моментом.

### 1. Норма-карточка, структурное обоснование, справочник типов (3 ч)

**Эффект.** Нормы 15: жюри видит дословную цитату, номер пункта, пометку «прямая/связанная», ссылку на рус/каз текст
adilet, и — отдельно — что система *не* утверждает (нет проводки, нет сверки). Это буквально формулировки ТЗ §5
(«без неподтверждённых предположений»), §6 («связь источник → нарушение → фрагмент») и §7 («не утверждать, если нужны
невидимые данные»). Продукт 10: результат читается без прокрутки одного абзаца.

**Данные уже есть** в `app/rules/norms.yaml`: `title, observable, conditions, exclusions, document, clause, url, quote,
quote2, interpretive, source_verified, train_examples`. Добавить одно поле на тип — `limits` («Что по видео
установить нельзя: факт проводки/сверки; это не юридическое заключение»); для типов с `interpretive: true` — текст
«прямого запрета в открытых актах РК нет; внутренние правила банка».

**API (Python `scripts/cashguard_analyzer.py` → Go `domain.Rule`, все поля `omitempty`, старые `title/section/url`
сохраняются):**
```json
"rule": {
  "title": "<document, как сейчас>", "section": "<clause, как сейчас>", "url": "<adilet rus>",
  "document_short": "Правила кассовых операций (пост. Правления НБРК № 231 от 29.11.2019)",
  "clause": "п. 20 (часть вторая); п. 22",
  "quote": "<дословно из yaml>", "quote2": "<если есть>",
  "interpretive": false,
  "url_kk": "https://adilet.zan.kz/kaz/docs/V1900019680",
  "observable": "<что должно быть видно>", "exclusions": "<когда это не нарушение>",
  "limits": "<что по видео установить нельзя>"
},
"explanation": { "observed": "...", "qualification": "...", "norm": "...", "quote": "..." }
```
`explanation` — те же куски, из которых `describe()` собирает `description` (разнести в `pipeline.py`: функция
`explain(e, norms) -> dict`, `describe()` склеивает её). Поле `description` для жюри не меняется.
`url_kk`: у adilet тот же код документа по пути `/kaz/docs/...` — официальный казахский текст без нашего перевода.

**Справочник:** скрипт `scripts/export_catalog.py` → `src/frontend/public/catalog.json` при сборке (Dockerfile): список
`{id, title, status: "detected"|"described_only", document_short, clause, quote, interpretive, observable, exclusions,
url, url_kk}`; `status` — есть ли включённый stump для типа в `models/scorer.json`. Без нового эндпоинта в Go.

**UI (`review-workspace.tsx`, event-detail):**
- три блока вместо абзаца: «Наблюдается» (факт, иконка глаза), «Квалификация», «Норма» — карточка: `document_short`,
  `clause`, `<blockquote>` с цитатой, бэдж «прямая норма» (зелёный) / «связанное требование» (янтарный), кнопки
  «adilet · рус» и «adilet · қаз»; раскрывашка «Что должно быть видно / Когда это не нарушение» (`observable`,
  `exclusions`); строка «Границы вывода» (`limits`) серым.
- новый пункт сайдбара «Справочник нарушений»: таблица 21 типа из `catalog.json` с фильтром «распознаётся /
  подготовлено описание», клик — та же карточка нормы. Это закрывает ТЗ §8 п. 5 прямо в продукте.

**Риск:** минимальный; единственная ошибка, которая стоит дорого — опечатка в пункте. Все цитаты уже сверены
(`normative_sources.md`), новых не вводить.

### 2. «Что проверено», паспорт анализа, предупреждения (4 ч)

**Эффект.** Продукт 10: `no_violation` становится результатом проверки, а не пустотой; видно, что сервис надёжно
обработал (режим, покрытие, время). Техника 10: sha256 + версия модели + режим = трассируемость, о которой банк спросит
первым («какая версия модели это решила?»). Устойчивость 10: на видео с нового ракурса объяснённый пропуск
(«дверь в кадре не найдена → проверка двери не проводилась») читается как честность, а не слабость (так рекомендует и 08
§6, и Veesion публикует список того, что не детектирует).

**Python (`app/analyzers/ml.py` → `AnalysisResult`, затем в JSON анализатора):**
```json
"checks": [
  {"id": "cashier_seat",   "status": "ok",      "label": "Рабочее место кассира найдено", "detail": "кассир на месте 98 % времени"},
  {"id": "coverage",       "status": "ok",      "label": "Проанализировано 0–118 с из 118 с", "detail": "2.0 кадр/с, режим полный"},
  {"id": "visitors",       "status": "ok",      "label": "Посетителей: 2", "detail": "визиты 00:12–00:58, 01:05–01:40"},
  {"id": "leave",          "status": "ok",      "label": "Уходов кассира с места: 0"},
  {"id": "door",           "status": "ok",      "label": "Дверь после входа закрывалась", "detail": "≤ 4 с"},
  {"id": "desk_items",     "status": "ok",      "label": "Предметы на столе между визитами не обнаружены", "detail": "OWLv2, 2 окна"},
  {"id": "phone_drink",    "status": "ok",      "label": "Телефон / напиток у кассира не обнаружены"},
  {"id": "safe",           "status": "skipped", "label": "Сейф в кадре не найден — проверка не проводилась"}
],
"warnings": ["мало времени: частота кадров снижена"],
"meta": {"analyzer_version": "<git sha>", "scorer_sha256": "<первые 12>", "mode": "full",
         "fps_analysed": 2.0, "frames_analysed": 236, "processing_sec": 97.4, "duration_sec": 118.0}
```
Источники данных уже в коде: `info["cashier_found"]`, `scene.seat`/сегменты, список `cands` по `kind` (leave, visit,
door, safe_key…), `info["owl_skipped"]`, `warnings`, `mode`, `last_t`. Статусы строго `ok | skipped | not_found`; никаких
«подозрительно» без события — иначе это скрытое событие без доказательства.

**Go:** `domain.Job` + `Checks []Check json:"checks,omitempty"`, `Warnings []string json:"warnings,omitempty"`,
`Meta *Meta json:"meta,omitempty"`; `CommandAnalyzer` копирует их из результата. В `upload()` считать sha256 через
`io.MultiWriter(out, sha)` → `Meta.VideoSHA256`; `received_at`, `finished_at` из уже существующих полей/времени;
`model_version` — `-ldflags "-X main.version=$(git rev-parse --short HEAD)"` в Dockerfile. `GET /api/jobs/{id}` при
`processing` отдавать `queue_position` (`len(s.queue)` на момент постановки) и `elapsed_sec`.
Для жюри (`juryResult`): добавить `checks` и `meta` как дополнительные поля — 08 §C1 допускает, `violations: []`
не трогать. При сомнении — только в UI-маршрут `/api/jobs/{id}`, жюри-схему оставить как есть.

**UI:** под вердикт-баннером блок «Что проверено» (чеклист с иконками ok/skipped, для `violation` — свёрнут); в шапке
страницы проверки «Паспорт анализа»: `sha256:ab12…`, `модель 7f3e…`, `режим полный`, `97 с`, `2.0 кадр/с`; жёлтая
полоса с `warnings`; в состоянии `processing` — «в очереди: 2 · прошло 01:12 из 05:00».

**Риск:** низкий; главное — не выдавать `checks` там, где данных нет (пустой список допустим).

### 3. «Почему так решено» + подсветка зоны на кадре (4 ч)

**Эффект.** Нормы 15 и доверие: каждое событие подкреплено числом, которое система измерила, и порогом, которому
обучилась — это сильнее любой «уверенности 0.63» и прямо отвечает «без неподтверждённых предположений». Локализация 15
оценивается автоматически, но на питче рамка на кадре делает «релевантность кадра-доказательства» очевидной.

**Python:** `Event` получает `metrics` и `regions`. `metrics` — из `models/scorer.json` (stump типа: имя признака,
порог, направление) и `e.f[name]`; словарь человеческих названий в `pipeline.py` (только для признаков с названием,
остальные не выдавать):
```json
"why": [{"label": "Яркость экрана относительно кадра после ухода", "value": 2.3, "threshold": 1.6, "op": ">=", "unit": "×"},
        {"label": "Кассир не вернулась до конца записи", "value": 1, "threshold": 1, "op": "==", "unit": ""}]
```
`regions` — нормализованные боксы (0..1) на каждый evidence-кадр из `Cand.extra` (`desk_box`, `key_box`,
`safe_zone`) и бокса кассира из трека на этом индексе `obs`; подпись `label` из фиксированного набора («кассир»,
«зона стола», «сейф», «экран», «дверь»). Кадр в API остаётся чистым JPEG — рисует UI.
```json
"evidence_frames": [{"timestamp_sec": 47.0, "image_base64": "...",
                     "regions": [{"x": 0.41, "y": 0.22, "w": 0.18, "h": 0.14, "label": "экран"}]}]
```
**Go:** `Frame.Regions []Region json:"regions,omitempty"`, `Violation.Why []Metric json:"why,omitempty"`.
**UI:** SVG-оверлей поверх `<img>` (viewBox 0 0 1 1, `preserveAspectRatio="none"`), переключатель «зоны» (по
умолчанию вкл.), в диалоге увеличения — тоже; список «Почему система так решила»: «значение 2.3× при пороге ≥ 1.6×»
в виде мини-шкалы (значение/порог). Для `interpretive`-типов тот же блок, без изменений.

**Риск:** средний. Неверная рамка хуже отсутствующей — выдавать только для типов, где бокс зоны стабилен (стол, сейф,
кассир); для `door_left_open` и `unauthorized_person` — только бокс человека. Проверить на 5–6 видео глазами.

### 4. Решение контролёра → журнал → «Акт проверки» (6 ч) — демо-момент

**Эффект.** Продукт 10: единственный полный сценарий «второй линии» (08 §8): алерт → проверка → решение → документ.
Техника 10: audit trail с версией модели и переопределением человеком — стандартный минимум для AI в банке
(EU AI Act ст. 12 логирование, ст. 14 человеческий надзор; аналоги: TRASSIR `confirmed/rejected` + эксперт, Verkada
PDF-отчёт инцидента + audit log). По ТЗ FAQ-27 не обязательно, поэтому рейтинг ниже, но на питче это главный кадр.

**Go (Postgres уже есть, `migrate.go`):**
```sql
CREATE TABLE reviews (id BIGSERIAL PRIMARY KEY, job_id TEXT NOT NULL, violation_index INT NOT NULL,
  decision TEXT NOT NULL CHECK (decision IN ('confirmed','rejected','needs_info')),
  reason_code TEXT, comment TEXT, reviewer TEXT NOT NULL, model_version TEXT, created_at TIMESTAMPTZ NOT NULL DEFAULT now());
CREATE TABLE audit_log (id BIGSERIAL PRIMARY KEY, job_id TEXT NOT NULL, actor TEXT NOT NULL, action TEXT NOT NULL,
  payload JSONB, created_at TIMESTAMPTZ NOT NULL DEFAULT now());
```
Действия в `audit_log`: `uploaded` (имя файла, размер, sha256), `analysis_done` (вердикт, число событий, режим, версия
модели, время), `review` (решение), `act_generated`.
Эндпоинты (UI-группа `/api`, с `X-API-Key` как сейчас):
- `POST /api/jobs/{id}/violations/{idx}/review` `{decision, reason_code, comment, reviewer}` → 201 + запись;
- `GET /api/jobs/{id}/reviews` → `[{violation_index, decision, reason_code, comment, reviewer, created_at}]`;
- `GET /api/jobs/{id}/audit` → список записей;
- `GET /api/jobs/{id}/act?lang=ru` → **HTML** (Go `html/template`, встроенный print-CSS, `@page A4`), кадры как
  `data:` URI из уже сохранённого результата, QR на `rule.url` через `github.com/skip2/go-qrcode` (MIT) → PNG data URI.
  PDF получается `window.print()` в UI — без библиотек на фронте и без внешних сервисов.

Коды причин отклонения (select): `values_stored_before_leave` «ценности убраны до ухода», `person_is_staff`
«посетитель — сотрудник банка», `client_present` «клиент в кадре», `frame_unreadable» «кадр не читается»,
`other`. Подтверждение: `confirmed` + необязательное «передать руководителю» (комментарий).

**Содержимое акта:** шапка (CashGuard · дата/время · файл · sha256 · длительность · версия модели · режим), вердикт,
по событию: №, тип, таймкод, 3 кадра с подписями `t−3 / t / t+8`, «Наблюдается / Квалификация», карточка нормы
(документ, пункт, дословная цитата, ссылка + QR), решение контролёра (кто, когда, причина), блок «Что проверено»
(из фичи 2), журнал аудита, дисклеймер ТЗ §7 («подсказка для проверки человеком, не юридическое заключение»). Поле
«Контролёр» — имя из `localStorage`, подписанное в UI как «идентификация для демо; в банке — SSO». Честно, без
выдуманной авторизации.

**UI:** в event-detail две кнопки «Подтвердить» / «Отклонить» (вторая открывает select причины + комментарий), бэдж
решения на карточке события в списке (✓/✗) и в истории; кнопка «Сформировать акт» рядом с «Скачать JSON» (активна
после ≥ 1 решения или для `no_violation` сразу); вкладка «Журнал» со списком `audit_log`.

**Риск:** объём (6 ч на троих — это 2 ч на слой). Минимальная версия за 3 ч: только `review` + акт без QR и без
отдельной вкладки журнала (журнал — в самом акте).

### 5. Полоса присутствия под таймлайном (3 ч)

**Эффект.** Продукт 10 и устойчивость: за одну секунду видно, где кассир был на месте, когда были посетители, что
проанализировано — это «тепловая карта» видео, которая объясняет и событие, и его отсутствие, и срез `cheap`-режима.

**Python:** из `scene` (сегменты сидения кассира, визиты) → 
```json
"timeline": {"cashier_at_seat": [[0, 46.5], [71.2, 118]], "visitors_present": [[12.0, 58.0]], "analysed": [[0, 118]]}
```
**Go:** `Job.Timeline *Timeline json:"timeline,omitempty"`.
**UI:** три тонкие дорожки под `<input type=range>` в `.timeline-track` (абсолютное позиционирование в процентах, как
маркеры), тултип с временем, легенда. Маркеры событий остаются сверху.

**Риск:** дырки в треке покажут «кассира нет» там, где он есть (стекло, перекрытия) — сглаживать сегменты < 1.5 с и
подписывать дорожку «по данным трекинга».

## 2. Дешёвые добавки (≤ 1 ч каждая), если останется время

- **Ссылка на казахский текст нормы** (`url_kk`, входит в фичу 1) — казахстанский контекст без риска плохого перевода.
- **Экономика ложных тревог** — не код, слайд/панель «Статистика»: «0 ложных на 40 видео (верхняя граница 95 % ≈ 7 %),
  тип верен 100 %, медиана таймкода 1.2–2 с; при 200 кассах × 8 ч → N проверок контролёра в день» из статического
  `models/metrics.json`, подписано «кросс-валидация по 7 постановкам камеры, обучающие данные». Ничего не выдумывать.
- **Копировать описание / ссылку на событие** (`#job/…/event/1`) — удобство демо.

## 3. Что НЕ делать

- **Перевод описаний и названий норм на казахский силами команды без носителя**: банковское жюри в Казахстане заметит
  кривой казахский быстрее, чем оценит его наличие. UI-хром уже на KK; нормы — через официальный `url_kk`.
- **Пакетная загрузка в UI**: ТЗ FAQ-27 — не нужна; при одном воркере и дедлайне от момента загрузки пять файлов подряд
  гарантированно сожгут бюджет хвоста (08 §C2). Если очень хочется — клиентская очередь «следующий файл после `done`
  предыдущего», но баллов это не добавит.
- **Сырой процент уверенности** в карточке события: одно-признаковые пороги дадут числа вроде 0.62 и вызовут вопросы;
  показывать измеренное значение и порог (фича 3).
- **Любой LLM-фритекст** в описании/акте; **PDF через внешний сервис/QR-API** (локальность, §7).
- Размывать лица на кадрах: ТЗ запрещает распознавание, не показ; размытие портит доказательство.

## 4. «Wow»-момент для 5-минутного питча (60–75 с внутри демо)

Одна история, заранее прогнанная (запасная запись по 08 §10):

1. Открываем результат видео «уход с места, экран активен» @ 00:47. Кадр с подсвеченной зоной «экран», под ним:
   «Яркость экрана 2.3× при пороге ≥ 1.6×; кассир не вернулась до конца записи» — *система показывает число, а не мнение*.
2. Карточка нормы: «Требования к ИБ банков (АРРФР № 53 от 03.04.2026), п. 71 подп. 9» — дословная цитата, бэдж
   «связанное требование», кнопки «adilet · рус / қаз». «Границы вывода: факт блокировки экрана по видео установить
   нельзя — нужен журнал АРМ».
3. Контролёр нажимает «Подтвердить» → «Сформировать акт» → открывается акт A4: кадры `t−3 / t / t+8`, пункт правил с QR,
   sha256 видео, версия модели, решение «подтверждено, Иванова А., 14:02». Фраза: **«От сигнала до акта — два клика, и в
   акте нет ни одного слова, которого система не измерила»**.
4. Переключаемся на второе видео — норма: вместо пустого экрана «Что проверено: кассир на месте 98 %, посетителей 2,
   дверь закрывалась за 3 с, предметов на столе между визитами нет, сейф в кадре не найден — не проверялся».
   Фраза: **«„Нарушений нет“ у нас — это результат восьми проверок, а не отсутствие модели»**.

Готовые ответы на Q&A, которые эти фичи дают бесплатно: «какая версия модели это решила?» (паспорт), «как контролёр
отменит ложное срабатывание?» (review + причина), «почему вы уверены, что это норма, а не пропуск?» (checks),
«откуда пункт правил?» (цитата + adilet рус/каз).
