## Что проверил и считаю ОК

- **HEVC .mov в `python:3.11-slim`**: `opencv-python-headless` (venv: cv2 5.0.0, `FFMPEG: YES, avcodec 62`) несёт собственный libavcodec со встроенным декодером HEVC; `apt` ffmpeg не нужен. Эмпирически подтверждено прогонами Х-26/Х-27/Х-14 на Railway. Поворот iPhone-метаданных: в cv2 ≥ 4.6 `CAP_PROP_ORIENTATION_AUTO` по умолчанию включён — кадры-доказательства будут в правильной ориентации.
- **Кириллица в имени файла**: Go хранит `id+ext`, имя только в БД; `filepath.Ext("Х-26.MOV")` → `.mov` (lowercase).
- **Контракт**: без ключа 401 JSON; неизвестный id → 404 JSON; `queued` наружу = `processing`; `failed` → `{status, error}`; 29 МБ ≪ 500 МБ; `ParseMultipartForm(8 МБ)` сбрасывает на диск.
- **Индексы кадров**: `Event.i` — индекс obs; `ml.py` берёт `obs[i].frame_id`; `frame_b64` ищет по `CAP_PROP_POS_FRAMES` с откатом −1…−12 кадров; fps для таймкода — тот же `sane_fps`. Согласованно, в т.ч. при 0.5 fps.
- **JSON без NaN**: `allow_nan=False`; все `f` в шаблонах — отфильтрованные медианы; типы из `STUMPS/RULES` все имеют шаблон.
- **Запас по времени**: Go −15 с, Python −20 с, `0.8·budget` на восприятие; CLIP на 290 кропов ≈ 15 с съедает часть запаса, но 285 < 300 держится (измерено 172 с на 143-с видео).
