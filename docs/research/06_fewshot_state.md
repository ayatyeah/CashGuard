# 06. Состояние зоны по 1–5 примерам: «что-то оставлено на столе», «сейф открыт», «ключ в замке»

Исследовательская записка (агент #6). Дата: 2026-10-17. Входные ограничения — `CONTEXT.md`: только локальный CPU/M3,
лицензии Apache-2.0 / MIT / BSD, 40 видео, 7 постановок камеры («кабинетов»), 1–3 позитива на тип.

## 0. Главный вывод (TL;DR)

1. **Классификаторы по позитивам (CLIP/SigLIP2 linear probe, Tip-Adapter, CoOp) для этих типов проверить честно нельзя.**
   Все позитивы «сейф открыт» (Х-20) и «ключ в замке» (Х-22) лежат в одном кабинете D; «деньги на столе при
   следующем клиенте» — Х-4 (кабинет A) и Х-38 (кабинет F), по одному на кабинет. При leave-one-cabinet-out
   позитивов нужного типа в обучении **ноль**. Значит работают только методы, которым нужны **только нормальные
   кадры** (anomaly detection / change detection), а порог калибруется на нормальных видео других кабинетов.
2. **Лучший кандидат — PatchCore/AnomalyDINO-стиль на патч-признаках DINOv2 ViT-S/14 (Apache-2.0) с банком
   «нормальных» патчей из того же видео** (стол до прихода клиента / сейф до того, как кассир к нему подошла) плюс
   банк нормальных конечных состояний из других кабинетов. Это прямое обобщение уже работающего `change_score`
   (пиксельная разность с маской людей) на семантические признаки: устойчивее к освещению, микросдвигам камеры,
   шуму JPEG, и даёт карту аномалий для кадра-доказательства. Оценка: 10–16 ч, ожидаемый выигрыш — надёжный
   `cash_left_on_desk` (Х-4/Х-38) и более устойчивый `safe_left_open`; «ключ в замке» — на грани разрешения
   (ключ ≈ 5–8 px в кадре 464×848), честно: детектор по одному позитиву без LOCO-подтверждения.
3. **DINOv3 не брать**: лицензия «DINOv3 License» (Meta, 14.08.2025) — кастомная, с обязательной надписью
   «Built with DINOv3», правом Meta менять условия, запретом ряда применений и выдачей весов по форме. Не входит в
   разрешённый список Apache/MIT/BSD. DINOv2 — Apache-2.0 (код и веса), SigLIP2 — Apache-2.0, SAM 2 — Apache-2.0,
   Cutie — MIT (код; лицензия весов не указана), anomalib — Apache-2.0, AnomalyDINO (код) — Apache-2.0, OpenCV — Apache-2.0,
   scikit-image — BSD.

## 2. Обзор методов

### 2.1 Патч-признаки DINOv2 + банк нормальных патчей (PatchCore / AnomalyDINO)

Суть. PatchCore (Roth et al., CVPR 2022): запоминаем патч-признаки нормальных изображений (банк памяти, coreset),
для тестового патча аномальность = расстояние до ближайшего соседа; оценка изображения = максимум (с перевзвешиванием).
Few-shot на MVTec-AD (image AUROC): 1 кадр — 83.4, 5 — 90.8, 10 — 93.6, 16 — 95.4 (PatchCore-10 %, WideResNet50).
AnomalyDINO (Damm et al., WACV 2025): то же, но признаки — последний слой DINOv2 ViT-S/14 (21M параметров) при
стороне 448/672, расстояние косинусное, оценка изображения = **среднее верхнего 1 % патч-расстояний**, маскирование
фона порогом по первой PCA-компоненте патч-признаков, аугментация эталонов поворотами. Результат 1-shot MVTec-AD
96.5–96.6 (против 83.4 у PatchCore и 93.1 у WinCLIP+), 4-shot 97.6; VisA 1-shot 85.6–87.4. Время ~60 мс/изобр. на A40;
банк для 1-shot строится 0.5 с. Код Apache-2.0, обучения нет вообще.

Что это даёт нам. Статическая камера — идеальный случай: «нормальные» патчи берём **из того же видео** (стол до
визита / сейф до подхода кассира), геометрия совпадает, значит nearest-neighbour почти сводится к сравнению тех же
мест, но в семантическом пространстве — пачка купюр, раскрытая дверца сейфа, светлая дверца вместо тёмной стенки
дают большое косинусное расстояние, а изменение яркости, тень, JPEG-шум — малое. Второй банк — нормальные конечные
состояния из других кабинетов — говорит, какие изменения «законны» (выключенный свет, закрытая крышка ноутбука,
сдвинутый стул) и снижает ложные срабатывания; он же единственный источник знаний при LOCO.

Известные слабости (из статьи): логические аномалии (неверная компоновка при нормальной локальной текстуре) — AUROC ≈
50 %; эталоны, не покрывающие нормальную вариацию → ложные; фон без маски; разрешение карты = патч 14 px. Для нас:
**ключ в замке (~5–8 px исходного кадра)** — при кропе сейфа ~100 px, растянутом до 448, один патч покрывает ~3 px
исходника, т. е. ключ ≈ 2×2 патча на интерполированных пикселях — сигнал, вероятно, слабый; нужен пиксельный путь (§2.2).

| Параметр | Оценка |
|---|---|
| Лицензия | DINOv2 Apache-2.0 (код+веса); timm/transformers Apache-2.0; faiss не нужен (numpy matmul) |
| CPU | ViT-S/14: 224² → 256 токенов ≈ 4.6 GFLOP ≈ 40–80 мс на 6 ядрах; 448² → 1024 токенов ≈ 250–400 мс. На видео нужно 10–30 кропов → 3–10 с. ViT-B — ×4 по времени, обычно без пользы в патч-NN |
| Сколько примеров | 0 позитивов; 3–8 нормальных кадров зоны из того же видео + (опционально) 20–60 нормальных кадров из других видео |
| Устойчивость к ракурсу | Высокая для внутривидеового банка (ракурс тот же); межвидеовой банк только добавляет «законные» состояния. Порог калибруется на нормальных видео 6 кабинетов |
| Трудоёмкость | 10–16 ч (извлечение, банк, скоринг, карта для доказательства, LOCO) |
| Ожидаемый выигрыш | +2 видео (Х-4, Х-38) при 0 FP реалистично; стабилизация Х-20; единая механика для `leave`/`next_visit`/`safe` |
| Риск | Средний: FP на законных перестановках (чашка, журнал) — лечится межвидеовым банком и площадью пятна; ключ не увидит |

### 2.2 Разность кадров с нормировкой освещения (SSIM / census / ZNCC) — улучшение текущего `change_score`

Суть. Census transform (сравнение пикселя с соседями → битовая строка) инвариантен к монотонным изменениям яркости;
ZNCC по окнам и SSIM (scikit-image, BSD) устойчивы к сдвигу среднего и контраста; гомоморфная фильтрация
(логарифм + ФВЧ) убирает множительную компоненту освещения (Toth, Aach, Metzler). Для статической камеры это самый
дешёвый способ увидеть мелкое: ключ в замке, пачка 15 px.

Рецепт: (а) кроп зоны ×2 (bicubic), (б) карта `1 − SSIM(win=7)` на яркости после CLAHE, плюс расстояние Хэмминга
census 5×5; (в) маска людей (дилатация 15 %, уже есть), (г) пятна: открытие 3×3, компоненты, компактность ≥ 0.35
(уже есть в `new_blob`), (д) **стойкость**: пятно должно сохраняться на ≥ 3 из последних 4 person-free кадров и быть
на том же месте (медиана центров), (е) признак = площадь стойкого пятна / ref_h². Для сейфа дополнительно сравнивать
только окрестность замка: место замка = медиана положения кистей кассира во время её стояния у сейфа
(`safe_zone` уже строится по кистям) — окно 0.15·ref_h вокруг.

| Параметр | Оценка |
|---|---|
| Лицензия | OpenCV Apache-2.0, scikit-image BSD-3 |
| CPU | миллисекунды на кроп |
| Примеры | 0 позитивов; порог = max по нормальным + запас |
| Ракурс | Внутривидеовое сравнение не зависит от ракурса; зависит от того, виден ли сейф/замок (в части кабинетов — нет → пропуск, не FP) |
| Трудоёмкость | 4–6 ч |
| Выигрыш | Единственный реалистичный путь к Х-22 (ключ); дешёвое снижение FP существующих `desk_change`/`safe_change` |
| Риск | Средний: тени от стоящего кассира, автоэкспозиция камеры; на 1 позитиве порог — «с запасом», без LOCO-гарантии |

### 2.3 Детекция оставленных предметов «как в видеонаблюдении» (dual background, MOG2/KNN)

Суть (Porikli, Ivanov, Haga 2008; обзор Luna et al., Sensors 2018, 18(12):4290): две модели фона с разной скоростью
обучения — быстрая впитывает остановившийся предмет за секунды, медленная — за минуты; пиксели «передний план в
медленной, фон в быстрой» = временно статичные объекты; далее фильтр «человек/не человек» (у нас — боксы YOLOX) и
проверка покинутости (владелец ушёл ≥ T с, в бенчмарках PETS2006/AVSS T = 30–60 с, у нас — «кассир встала и
не вернулась»). Tian et al. (ECCV 2008) добавляют различение «оставлено» vs «унесено» (ghost) по тому, совпадают ли
границы пятна с градиентами текущего кадра или фона. В OpenCV: `cv2.createBackgroundSubtractorMOG2(history, varThreshold,
detectShadows)` / `createBackgroundSubtractorKNN`; `apply(frame, learningRate)` — `0` замораживает модель, `-1`
автоматически, `1` переинициализирует с текущего кадра; `bgsegm` (contrib) содержит ViBe-подобные GSOC/CNT/LSBP.

Для нас честная оценка: видео 10–145 с при 2 fps в кэше — 20–290 кадров; «медленная» модель едва успевает
сформироваться, кассир перекрывает стол большую часть времени, свет выключают. Проще и надёжнее эквивалент
«вручную»: эталон = медиана person-free кадров до события, тест = person-free кадры после (это то, что уже делает
`change_score`). MOG2 имеет смысл только как генератор кандидатов «что-то новое появилось в кадре и лежит ≥ 5 с»
на полном кадре (без привязки к зоне), для неизвестных типов нарушений.

| Лицензия | OpenCV Apache-2.0 (bgsegm — contrib, Apache-2.0) |
|---|---|
| CPU | десятки мс/кадр на 464×848 |
| Примеры | 0 |
| Ракурс | не зависит |
| Трудоёмкость | 6–10 ч с «ghost»-логикой и тестами |
| Выигрыш | Небольшой поверх §2.1–2.2; полезно как общий «оставлен предмет» для новых типов |
| Риск | Высокий FP: тени, свет, стул; короткие видео |

### 2.4 SigLIP2 / CLIP: zero-shot, Tip-Adapter, linear probe

Факты. SigLIP2 — Apache-2.0; варианты base-p16 (224/256/384/512, 0.4B), large (0.9B), so400m-p14/p16 (1B), giant
(2B), NaFlex (динамическое разрешение). Tip-Adapter (ECCV 2022) — безобучный key-value кэш из few-shot примеров,
в 1-/2-shot сильно лучше linear probe; Tip-Adapter-F дообучает кэш. На CPU so400m@384 ≈ 1–2 с/кроп, base@256 ≈
0.1–0.2 с.

Почему для наших трёх типов это не основной путь: (а) нужны позитивы, а их при LOCO нет; CLIP linear probe на
кропах стола уже ухудшил CV (ml_model.md); (б) глобальный эмбеддинг кропа смешивает сцену и ракурс — 1 позитив из
кабинета D определяет «ракурс D», а не «открытый сейф». Что всё же можно: **zero-shot разность** — не классификация
кропа, а изменение логита «an open safe with the door ajar» − «a closed metal safe» между эталонным и конечным
кадром **того же видео**; порог на нормальных. То же для «banknotes lying on a desk» (уже есть в `PROBES`).
Эффект, скорее всего, слабее DINOv2-патчей (кропы маленькие, объекты занимают < 10 % кропа), но это 2–3 ч и
даёт независимый второй сигнал для ансамбля согласия (как уже сделано для VLM+короткий визит).

| Лицензия | SigLIP2 Apache-2.0; CLIP ViT-B/32 MIT |
|---|---|
| Примеры | zero-shot: 0; Tip-Adapter: 1–16 позитивов (у нас нет) |
| Ракурс | zero-shot разность — не зависит; linear probe — переобучается на кабинет |
| Трудоёмкость | 2–3 ч (zero-shot разность), 4–6 ч (Tip-Adapter, без возможности честно оценить) |
| Выигрыш | Низкий–средний, как второй голос |
| Риск | Средний: промпт-чувствительность; so400m медленный на CPU |

### 2.5 PaDiM (пер-позиционная гауссиана) — вариант §2.1 для статической камеры

PaDiM (Defard et al., 2020): для каждой позиции патча — многомерная гауссиана по нормальным изображениям, оценка =
расстояние Махаланобиса. На MVTec few-shot заметно хуже PatchCore (1-shot 76.1 vs 83.4; 16-shot 85.5 vs 95.4), потому
что позиции между изображениями не выровнены. У нас камера неподвижна и позиции выровнены идеально внутри видео, но
нормальных кадров зоны всего 3–10 → ковариацию не оценить (нужна сильная усадка к диагонали или просто z-score по
каналам). Практически: пер-позиционный NN из §2.1 с окном ±1 патч даёт то же без статистики. Отдельно не внедрять;
оставить как ablation «NN по всему банку vs NN в окне ±1 патч» (второе строже и чувствительнее к мелким предметам).

### 2.6 SAM 2 / Cutie — трекинг состояния области

SAM 2 — Apache-2.0 (код и веса), Cutie — MIT (код; лицензия весов на странице не указана, демо ориентировано на CUDA).
Назначение — сегментировать объект на первом кадре и вести маску по видео. Для статической камеры и зон, заданных
боксами, трекинг не нужен; «состояние региона» лучше измерять сравнением с эталоном. Возможное применение — маска
дверцы сейфа по клику (один раз в кабинете) для точной области сравнения, но на новом ракурсе жюри клика нет →
не подходит под «устойчивость к новой камере». SAM 2 на CPU: hiera-tiny ≈ 1–3 с/кадр. Не рекомендую.

### 2.7 Что ещё смотрел и отклонил

- WinCLIP / APRIL-GAN / AnomalyCLIP (zero-/few-shot AD на CLIP): WinCLIP+ 1-shot MVTec 93.1 (ниже AnomalyDINO),
  APRIL-GAN требует обучения проекции на вспомогательном датасете, AnomalyCLIP учит промпты — лишняя сложность
  при тех же признаках; промышленные датасеты не похожи на кассу.
- anomalib (Apache-2.0): PatchCore/PaDiM с timm-бэкбонами по именам слоёв CNN; ViT-токены DINOv2 через `layers`
  штатно не поддерживаются — проще 100 строк своего кода, чем адаптировать фреймворк и тащить Lightning в рантайм.
- Scene change detection с DINOv2 + cross-attention (Lin et al., 2024): нужна обучающая выборка пар; наш случай —
  тождественное преобразование между кадрами, достаточно косинусной карты.

## 4. Рецепт №1: PatchCore/AnomalyDINO на DINOv2 поверх кэша кадров

### 4.1 Модель
- `facebook/dinov2-small` (transformers, Apache-2.0) или `torch.hub dinov2_vits14_reg` (вариант с регистрами — без
  артефактных токенов, что важно именно для патч-NN). Патч 14, 384-мерные токены последнего слоя, L2-нормировка.
  Веса кладём в локальный кэш, как CLIP (`HF_HUB_OFFLINE=1`). Экспорт в ONNX опционален (на Mac — torch MPS).
- Разрешение кропа: короткая сторона 224 для зон < 120 px в кадре (растягивать сильнее бессмысленно), 448 для
  крупных зон стола; размеры кратны 14. Яркость: CLAHE по L-каналу перед энкодером (унификация «свет включён/выключен»).

### 4.2 Зоны и кадры (всё уже есть в `candidates.py`)
- `desk` = `hand_zone()` для `next_visit`, `static_regions()[0]` для `leave`; `laptop` вычитать из маски стола
  (как сейчас) и считать отдельно как `screen_anom`; `safe` = `safe_zone()` с pad 0.6 (как сейчас).
- Эталонные кадры R (нормальное состояние, 3–8 шт.), всегда person-free по `_box_overlap(zone, _persons(obs, 0.3))`:
  - `next_visit`: кадры от начала визита A до момента, когда клиент A сел + 1 с? Нет — **до прихода клиента A**
    (стол пуст) или, если видео начинается с клиента, последние person-free кадры перед визитом A; тест T = последние
    4 person-free кадра промежутка между визитами (как в текущем коде `gap[-4:]`);
  - `leave`: R = person-free кадры стола до/в начале (если нет — кадры, где кассир сидит, с маской её бокса +15 %);
    T = `late` после ухода (`free`);
  - `safe`: R = person-free кадры до первого стояния у сейфа (`ref_i`), T = `late[-4:]` после последнего ухода от сейфа.
- Маска патчей: патч исключается, если ≥ 30 % его площади попадает в бокс человека (дилатация 15 %) — в R и в T.

### 4.3 Банк и оценка
```python
# feats(img_bgr, zone_box, scale) -> (N, 384) L2-норм. патч-признаки + их (row, col)
M_video = concat(feats(frames[i], zone)[~masked] for i in R)            # 3–8 кадров → 0.8–8k патчей
M_norm  = load("models/norm_bank_<zone>.npy")                              # нормальные конечные состояния других кабинетов
def score(frame):
    f, rc = feats(frame, zone); f = f[~masked]
    d_vid  = 1 - (f @ M_video.T).max(1)                                    # косинусное расстояние до своего эталона
    d_norm = 1 - (f @ M_norm.T).max(1)
    d = np.minimum(d_vid, d_norm)                                         # «законно», если похоже на нормальное хоть где-то
    img = np.sort(d)[-max(1, len(d)//100):].mean()                         # mean top-1 % (AnomalyDINO)
    amap = upsample(d -> zone crop) ; blob = largest_compact_component(amap > tau_pix)
    return img, blob_area / ref_h**2, blob_bbox
video_feature = median(score(frames[j])[0] for j in T)                     # как сейчас: медиана по последним 4 кадрам
```
- Аугментация эталонов (аналог поворотов в AnomalyDINO): сдвиги ±4 px, масштаб ±5 %, гамма 0.8/1.25 — покрывает
  микродрожь камеры и автоэкспозицию. Для 3–8 кадров это ×6 патчей, брутфорс matmul остаётся < 50 мс.
- Межвидеовой банк `M_norm`: патчи конечных person-free кадров зоны из **нормальных** видео других кабинетов
  (при LOCO — только из обучающих кабинетов), по 2 кадра на видео, coreset до ~5–10k патчей (жадный farthest-point,
  как в PatchCore). Он снимает ложные «аномалии» на выключенном свете, закрытой крышке ноутбука, пустом стуле.
- Признаки в `FEATS`: `desk_anom` (мера), `desk_anom_blob` (площадь стойкого пятна, нормированная ref_h²),
  `safe_anom`, `screen_anom`. Решение — те же пни скорера с правилом «max по нормальным + запас» или
  `median + 4·MAD` по нормальным; выбираем то, что даёт 0 FP на LOCO.
- Кадр-доказательство: кадр из T с наибольшей оценкой, bbox пятна карты аномалий поверх зоны (объяснимость для жюри).

### 4.4 Бюджет времени
10–30 кропов на видео × 0.05–0.4 с = 1–10 с на CPU Ryzen 5600H; на M3 (MPS) в 2–4 раза быстрее. Укладывается в
текущий ≈1× реального времени с запасом; при нехватке бюджета — режим `cheap`: только 224 и только 2 тестовых кадра.

### 4.5 Что ожидать по типам
- `cash_left_on_desk` (Х-4, Х-38): пачка ~15 px на столе ~150 px → при 448 это ~3×3 патча с сильно отличающейся
  семантикой (бумага/купюры на фоне стола) — хороший случай; `desk_blob` уже видел сигнал, проблема была в FP, с
  которыми борются `M_norm` и критерий стойкости.
- `left_cash_unattended` (Х-15, Х-24, Х-26): зелёная сумка / журнал и печати — крупные объекты, уверенно.
- `safe_left_open` (Х-20): открытая дверца меняет большую часть зоны — уверенно (сейчас 0.108 vs ≤ 0.052).
- `safe_key_left` (Х-22): объект ниже разрешения патчей; ожидаемо слабый сигнал. Решение — §2.2 (окно замка,
  SSIM/census) как отдельный признак `lock_change`; порог по нормальным Х-21, Х-23, Х-25, Х-27, Х-29, Х-12.
- `workstation_unlocked` (Х-11, Х-28): текущий признак яркости работает; `screen_anom` — страховка при изменении
  ракурса (экран виден под углом).

## 5. Валидация leave-one-cabinet-out

1. Разбиение: 7 кабинетов из `configs/cabinets.json` (дубликаты Х-47≡Х-4, Х-48≡Х-5 — в группу оригинала).
2. Для каждого выпадающего кабинета K: `M_norm` и пороги строятся **только** на нормальных видео остальных 6
   кабинетов (внутривидеовой банк в тесте остаётся — он не содержит разметки). Тест — все видео K.
3. Метрики на уровне видео: AUROC признака по 40 видео (чтобы видеть разделимость до порога); при пороге «0 FP на
   обучающих нормальных»: recall по типам (отдельно для Х-4/Х-38, Х-15/Х-24/Х-26, Х-20, Х-22), FP на нормальных
   видео K; ошибка таймкода (момент — как сейчас: `te = max(a1, b0 − 3)` для `next_visit`, `t_leave` для `safe`).
4. Базовая линия — текущие `desk_change`/`desk_blob`/`safe_change` на тех же кадрах и масках: сравнение пар
   (AUROC, запас между max нормальных и min позитивов — «margin»). Признак принимается, если margin не хуже и FP не
   растёт; это тот же критерий, по которому включались VLM-признаки.
5. Абляции (по одному прогону каждая, кэш признаков на диск): ViT-S vs ViT-B; 224 vs 448; с/без `M_norm`; mean
   top-1 % vs max vs NN в окне ±1 патч; с/без CLAHE; с/без аугментации эталонов. Фиксируем конфигурацию до
   финального прогона на всех 40, чтобы не подгонять под тест.
6. Контроль честности: типы с единственным позитивом (Х-20, Х-22) при LOCO оцениваются как «обнаружен / не
   обнаружен при порогах, не видевших кабинет D»; в отчёте помечать, что порог для них не имеет статистической опоры.
