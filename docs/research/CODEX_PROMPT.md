# Промпт для Codex (второй раунд исследования и прототипирования)

Скопируй блок ниже целиком в Codex, запуская его из корня репозитория `ForteWin` (ветка `aslan-18gb` или `ayat`).

---

Ты работаешь над проектом ForteWin — локальный AI-сервис для хакатона ForteBank (Казахстан): по видео с одной камеры
над кассой банка (.mov, 464×848, 30 fps, 10–145 с) определить признаки нарушений кассовой дисциплины и вернуть
вердикт, события с таймкодом, кадры-доказательства, описание и ссылку на пункт норматива РК.

**Сначала прочитай, в этом порядке:**
1. `docs/research/CONTEXT.md` — постановка, ограничения, метрики, что уже пробовали и отвергли.
2. `docs/research/01..10_*.md` — отчёты 10 исследовательских агентов (детекторы, VLM для Mac, действия/руки,
   датасеты/синтетика, практика индустрии, few-shot состояния зон, независимость от ракурса, тактика баллов,
   производительность на Apple Silicon, нормативы и таксономия нарушений).
3. `docs/ml_model.md`, `docs/train_timelines.md`, `STACK.md`, `app/ml/*.py`, `scripts/train_scorer.py`.

**Жёсткие ограничения (нарушение = дисквалификация или ноль баллов):**
- только локальный инференс, никаких облачных AI-API; никакого распознавания лиц;
- лицензии кода и весов — разрешающие коммерческое использование (Apache-2.0 / MIT / BSD); не брать GPL/AGPL,
  CC-BY-NC, research-only; лицензию проверять на первоисточнике, а не по памяти;
- рантайм: Mac M3 Pro 18 ГБ (MLX / CPU / CoreML), 5 минут на видео от момента загрузки, включая очередь;
- данные: 40 видео в `data/` (видео нельзя публиковать и выносить); тестовые видео жюри нельзя использовать для обучения;
- любое изменение модели принимается **только если не ухудшает leave-one-cabinet-out** кросс-валидацию
  (`python scripts/train_scorer.py --vlm-confirmed --with-vlm` печатает её; сейчас 0.725 точности / 0 ложных;
  финальная модель на всех 40: 0.825 / 0 ложных). Ложные срабатывания дороже пропусков для репутации, но пропуски
  по ТЗ «недопустимы» — целимся в recall при FP = 0.

**Твоя задача — три этапа, по каждому отдельный короткий отчёт в `docs/research/codex_<этап>.md`:**

Этап 1. Критически перепроверь отчёты агентов: лицензии (открой первоисточники), заявленные скорости и метрики,
применимость к объектам 10–40 px на кадре 464×848. Отметь, что из их рекомендаций ошибочно или устарело.
Собери единый ранжированный список идей по формуле (ожидаемый прирост баллов / часы работы), с учётом того,
что до сдачи — считанные дни и команда из 3 человек.

Этап 2. Прототипируй топ-3 идеи на наших кэшированных кадрах (`data/cache/frames/<video>/*.jpg`, 2 fps, разметка
в `configs/train_annotations.json`, интервалы посетителей в `configs/visitors_train.json`, кабинеты в
`configs/cabinets.json`). Приоритетные пропуски: деньги предыдущего клиента на столе при входе следующего (Х-4, Х-38),
содержимое инкассаторской сумки убрано в сейф без пересчёта (Х-13), ключ оставлен в замке сейфа (Х-22), приём денег
без документа клиента (X-2), деньги отданы клиенту обратно (X-1), отбракованные купюры вложены в пачку (Х-44).
Для каждого прототипа: признак → значения на всех 40 видео → разделяет ли позитивы и негативы → добавить как
кандидат в `app/ml/candidates.py` + stump в `app/ml/scorer.py` (см. как сделано `safe_open`) → прогнать обучение →
принять только если кабинетная CV не упала. Веса моделей клади в `models/` (игнорируется гитом), скачивание —
в `scripts/download_models.sh`. Не загружай ничего тяжелее ~2 ГБ без явной необходимости.

Этап 3. Если среди идей есть смена/добавление VLM или дообучение — подготовь всё для запуска на Mac
(инструкция в `docs/mac_18gb.md`, генератор пар `scripts/make_vlm_sft.py`): команды, ожидаемое время, критерий
успеха на валидационных кабинетах C и E. Сам на Linux тяжёлые модели не запускай.

**Правила работы:** коммить в ветку `codex` небольшими коммитами с понятными сообщениями; тесты
`python -m pytest tests -q` должны проходить; ничего из `data/` в git не попадает; в документации — только
проверенные факты с ссылками, без «вероятно» без пометки. В конце — сводка: что принято, что отвергнуто и почему,
обновлённая таблица метрик.
