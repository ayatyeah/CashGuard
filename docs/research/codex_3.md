# Этап 3 — подготовка Mac/SFT, 17.10.2026

Результат: подготовлен воспроизводимый **эксперимент**, новая модель не принята. Тяжёлые модели на Linux
не запускались, веса не скачивались; прирост и скорость на M3 Pro **не измерены**.

Исправлены `docs/mac_18gb.md` и существующий `scripts/make_vlm_sft.py`:

- Убраны обещания скорости/памяти, автоматической выгоды 8B и невозможности таймаута. Рекомендация — сначала 4B A/B.
- API проверен по [исходнику MLX-VLM, commit 73d366e](https://github.com/Blaizzy/mlx-vlm/blob/73d366ecf9233b3fc6549531a7f2386726d09ff6/docs/training.md):
  актуальный модуль `mlx_vlm.train`, `--data`, `--adapter-file`; старого `mlx_vlm.lora` в дереве main нет.
  Генератор пишет `images: [...]`, `validation.jsonl`; относительные пути разрешаются из папки split.
- [MLX-VLM — MIT](https://github.com/Blaizzy/mlx-vlm/blob/main/LICENSE),
  [Qwen3-VL-4B-Instruct — Apache-2.0](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct).
  Сам файл LICENSE в HF по проверенному пути вернул 404; утверждение о весах основано на официальной карточке.
- `None` больше не обучается как false. Неизвестный кабинет и одинаковые изображения между split вызывают ошибку;
  непустой output не перезаписывается. C/E исключены из train; аугментация train отключена по умолчанию.
- Добавлен манифест с исходными frame IDs, кабинетами, hash пикселей и явной маркировкой слабых меток.
  Разметка целого видео не гарантирует наличие объекта в конкретной мозаике: обязательна локальная проверка строк.
- C/E — holdout только для нового адаптера, не независимый test уже обученного пайплайна. Для полноценной LOCO
  адаптер/трекер/пороги требуется обучать заново внутри внешнего fold. Один SFT на A/B/D/F/G это не заменяет.
- Даны команды smoke training и Python-загрузки адаптера. Текущий runtime не подключает адаптер автоматически;
  deployment и fuse не объявлены проверенными. Старые гарантии таймаута неверны из-за startup, min budget и evidence.

Проверки без MLX/весов:

```text
.venv/bin/python -m pytest tests/test_make_vlm_sft.py -q
2 passed
.venv/bin/python scripts/make_vlm_sft.py --dry-run
train 77, val 11; без записи файлов
.venv/bin/python scripts/make_vlm_sft.py --out data/sft_codex_check --val-cabinets C,E --aug 0
train 77, val 11; 88 изображений и JSON-строк проверены чтением
```

Проверены все 88 относительных image paths через OpenCV, boolean JSON-ответы, соответствие C/E → val,
отсутствие пересечения видео и аугментаций val. Артефакты только в игнорируемом `data/`.
Val содержит between=1, teller=7, visitor=3, **не содержит desk/safe**: нельзя заявить улучшение ключа в замке
или unattended-desk по этому split. Добавлять новые кадры можно только с разметкой и сохранением групп по кабинетам.
Скорость SFT/инференса, качество 4B и совместимость полного Mac runtime остаются непроверенными;
критерий принятия и бюджетные оценки приведены в `docs/mac_18gb.md`.
