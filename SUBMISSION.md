# CashGuard — материалы к сдаче (Datathon 26, кейс ForteBank)

Соответствует разделу 8 ТЗ. Все модели и код работают локально; облачные AI-сервисы не используются;
распознавания лиц нет.

## 1. Адреса и доступ
- **Интерфейс:** https://fortecashguard.up.railway.app
- **API (ТЗ §10):** `POST https://fortecashguard.up.railway.app/api/v1/analyze` (multipart, поле `file`) →
  `{"job_id": ..., "status": "processing"}`; `GET https://fortecashguard.up.railway.app/api/v1/jobs/{job_id}` →
  `processing | done | failed`, при `done` — `verdict`, `violations[]` (`type`, `timecode_sec`, `description`,
  `evidence_frames[]{timestamp_sec, image_base64}` — JPEG без префикса `data:`), `rule {title, section, url}`.
- **API-ключ для жюри:** заголовок `X-API-Key: <передаётся организаторам отдельно>`. Без ключа — HTTP 401.
- Пример:
  ```bash
  curl -X POST https://fortecashguard.up.railway.app/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
  curl https://fortecashguard.up.railway.app/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
  ```
- Резервный контур (с визуально-языковой моделью на Apple Silicon): `docs/mac_18gb.md`, `docs/deploy_mac.md`.

## 2. Запуск и использование
- Облако (текущий стенд): `docs/deploy_railway.md` — один контейнер (`Dockerfile`): React-интерфейс, Go API, Python-анализатор.
- Локально: `docker compose up -d --build` (README, раздел CashGuard) или `src/backend/Dockerfile.ml`.
- Анализатор отдельно: `bin/cashguard-analyzer <video.mov> [budget_sec]` → JSON в stdout (`scripts/cashguard_analyzer.py`).
- Интерфейс: загрузить `.mov` → статус обработки → вердикт, события с таймкодами, кадры-доказательства, норматив.

## 3. Архитектура и модели
`docs/ml_model.md` (подробно), кратко:
- восприятие: YOLOX-M/S (COCO, ONNX, Apache-2.0), RTMPose-m (Apache-2.0), CLIP ViT-B/32 (MIT), OWLv2-base (Apache-2.0);
  опционально Qwen3-VL (Apache-2.0) на Mac/MLX;
- сцена без координат камеры: трекинг людей, рабочее место кассира, все признаки в долях роста кассира;
- события: уход с места, дверь после входа, посетитель не садится, короткий визит, предметы на столе между клиентами
  (OWLv2), ключ в замке сейфа (OWLv2), сейф не закрыт, напиток, телефон;
- решающий слой: по одному признаку и обученному порогу на тип (`models/scorer.json`), отбор признаков по
  leave-one-cabinet-out; функция потерь 2·пропуск + ложное;
- бюджет времени: от загрузки файла, адаптивная частота кадров, тяжёлые модели — только при запасе времени; ответ приходит всегда.

Метрики на 40 видео (`docs/ml_model.md`): кросс-валидация по 7 постановкам камеры **0.775** точности вердикта,
**0 ложных**; на всех 40 — 0.90 / 0 ложных; тип события верен у 100 % найденных; медиана ошибки таймкода 1.2–2 с.

## 4. Нормативные источники и сопоставление
`docs/normative_sources.md`, `app/rules/norms.yaml` — 21 тип, каждый с документом, пунктом и дословной цитатой,
сверенной с adilet.zan.kz (НБРК № 231 от 29.11.2019 — основной; № 14 от 24.02.2020; АРРФР № 53 от 03.04.2026).
Связанные (непрямые) нормы помечены `interpretive` и в описании подписаны «связанное требование».
Описание события строится из измеренных признаков: «Наблюдается / Квалификация / Норма + цитата».

## 5. Типы нарушений (распознаются)
См. `docs/violations_train.md` и `app/rules/norms.yaml`: ушёл, оставив наличные/ценности; рабочая станция не
заблокирована; дверь не закрыта; посторонний в кассе; пересчёт не при клиенте; деньги предыдущего клиента на столе
при следующем; сейф оставлен открытым; ключ в замке; личные вещи на столе; еда/напитки; телефон; инкассаторская
сумка без проверки; кассир ушёл при ждущем клиенте. Для типов без детектора (выдача без пересчёта, возврат денег
клиенту, передача третьему лицу, отбраковка) подготовлены описания и нормы.

## 6. Ограничения и известные ошибки
- Не распознаются: приём денег без документа, возврат денег клиенту, вскрытие сумки без пересчёта, вложение
  отбракованных купюр — требуют детектора последовательности действий рук, на наших ракурсах он нестабилен.
- Типы с 1–2 обучающими примерами (сейф, ключ, личные вещи, напиток) — пороги без статистической опоры; на новом
  ракурсе возможны пропуски (не ложные срабатывания — модель настроена на 0 ложных).
- В облаке CPU общий: на длинных видео анализ идёт с пониженной частотой кадров; при 5 одновременных загрузках
  хвост очереди получает урезанный бюджет.
- Результат — подсказка для проверки человеком, не юридическое заключение (см. описание каждого события).
- Исследование и отклонённые идеи: `docs/research/00_SUMMARY.md`, `docs/ml_model.md`.
